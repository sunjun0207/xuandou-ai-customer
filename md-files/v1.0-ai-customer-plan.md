# v1.0 会话列表：表结构、接口与业务逻辑

库名与 frp 相同，是 `xuandou_ai_workflow`。字符集 `utf8mb4`。frp 进程启动时执行下面的 `CREATE TABLE IF NOT EXISTS`。客服窗口自己不连接 MySQL。

左侧会话不再写入浏览器 `localStorage`。同一个登录名在 Chrome、Edge 或另一台电脑上打开，都向数据库要同一份列表。重命名、置顶、删除也写回这张表。刷新页面、换浏览器之后还在。

消息传输日志仍在 `message`。会话列表不直接扫那张表：`conversationId` 原来只躺在 JSON 正文里，没有列，也没有标题、置顶和删除标记。下面两张表专门给会话列表用。`conversation_message.id` 与产生它的 `message.id` 相同。

## 表结构

### conversation

一个登录名的一条会话一行。主键是会话编号。

| 字段 | 类型 | 空 | 说明 |
| --- | --- | --- | --- |
| id | VARCHAR(64) | 否 | 会话编号，主键。新会话是雪花 ID。更早的会话可能是字母和数字 |
| user_id | VARCHAR(64) | 否 | 所属登录名，例如 `admin`。列表按这个字段隔离，不按用户数字主键 |
| title | VARCHAR(80) | 否 | 会话标题。默认「新的对话」 |
| renamed | TINYINT | 否 | 1 表示用户改过标题，之后的消息不再覆盖标题。0 表示仍可按第一条用户消息生成标题 |
| pinned | TINYINT | 否 | 1 置顶，0 未置顶 |
| pinned_at | DATETIME(3) | 是 | 置顶时间，北京时间。置顶会话按它倒序。取消置顶后为空 |
| created_at | DATETIME(3) | 否 | 创建时间，北京时间 |
| updated_at | DATETIME(3) | 否 | 最近一条消息、改名或置顶的时间，北京时间 |
| deleted_at | DATETIME(3) | 是 | 删除时间。非空表示已从列表隐藏。消息行不物理删除 |

索引：

- 主键 `id`
- `idx_user_list (user_id, deleted_at, pinned, updated_at)`：按登录名取未删除会话，置顶在前

```sql
CREATE TABLE IF NOT EXISTS conversation (
  id VARCHAR(64) NOT NULL COMMENT '会话编号。新会话是雪花 ID，旧会话可能是字母数字',
  user_id VARCHAR(64) NOT NULL COMMENT '所属登录名。同一个账号在各浏览器看到同一批会话',
  title VARCHAR(80) NOT NULL DEFAULT '新的对话' COMMENT '会话标题',
  renamed TINYINT NOT NULL DEFAULT 0 COMMENT '1 表示用户改过标题，之后的消息不再覆盖标题',
  pinned TINYINT NOT NULL DEFAULT 0 COMMENT '1 置顶，0 未置顶',
  pinned_at DATETIME(3) NULL COMMENT '置顶时间。置顶的会话按这个时间倒序',
  created_at DATETIME(3) NOT NULL COMMENT '创建时间，北京时间',
  updated_at DATETIME(3) NOT NULL COMMENT '最近一条消息、改名或置顶的时间，北京时间',
  deleted_at DATETIME(3) NULL COMMENT '删除时间。非空表示已从列表隐藏，消息行仍保留',
  PRIMARY KEY (id),
  KEY idx_user_list (user_id, deleted_at, pinned, updated_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### conversation_message

会话里的一帧消息一行。流式输出的每一小段也是一行，读出来时再按 `stream_id` 拼成一条气泡。

| 字段 | 类型 | 空 | 说明 |
| --- | --- | --- | --- |
| id | BIGINT UNSIGNED | 否 | 消息雪花 ID，主键，与 `message.id` 相同 |
| conversation_id | VARCHAR(64) | 否 | 所属会话编号 |
| user_id | VARCHAR(64) | 否 | 会话所属登录名。查询时同时核对，避免靠猜编号读到别人的消息 |
| client_msg_id | VARCHAR(64) | 否 | 浏览器生成的消息编号。用户发出的那条和库里的雪花 ID 用它对齐。没有时为空字符串 |
| stream_id | VARCHAR(64) | 否 | 流式回复编号。同一次回复的 `delta` 和 `done` 共用。普通消息为空字符串 |
| role | VARCHAR(16) | 否 | `user` 用户，`assistant` 助手，`system` 系统 |
| kind | VARCHAR(16) | 否 | `chat`、`confirm`、`progress`、`result`、`file`、`delta`、`done`、`user` |
| body | MEDIUMTEXT | 否 | 这一帧的正文。读列表时不返回正文，打开会话才取出 |
| project_id | VARCHAR(64) | 否 | 项目编号。没有时为空字符串 |
| problem_id | VARCHAR(64) | 否 | 问题编号。没有时为空字符串 |
| request_id | VARCHAR(64) | 否 | 确认请求编号。没有时为空字符串 |
| stage | VARCHAR(40) | 否 | 进度阶段名 |
| url | VARCHAR(512) | 否 | 结果链接或文件链接 |
| decision | VARCHAR(16) | 否 | 确认决定：`accept`、`reject`，或空字符串 |
| file_name | VARCHAR(120) | 否 | 文件名 |
| percent | INT | 否 | 进度百分比，0 到 100。没有进度时为 -1 |
| created_at | DATETIME(3) | 否 | 消息时间，北京时间 |

索引：

- 主键 `id`。重复入库使用 `INSERT IGNORE`，同一帧不会写两行
- `idx_conv (conversation_id, id)`：按会话取出最近 200 条
- `idx_user (user_id, conversation_id)`：按登录名限制可见范围

```sql
CREATE TABLE IF NOT EXISTS conversation_message (
  id BIGINT UNSIGNED NOT NULL COMMENT '消息雪花 ID，与 message.id 相同',
  conversation_id VARCHAR(64) NOT NULL COMMENT '所属会话编号',
  user_id VARCHAR(64) NOT NULL COMMENT '会话所属登录名',
  client_msg_id VARCHAR(64) NOT NULL DEFAULT '' COMMENT '浏览器生成的消息编号',
  stream_id VARCHAR(64) NOT NULL DEFAULT '' COMMENT '流式回复编号。同一条回复的增量共用',
  role VARCHAR(16) NOT NULL COMMENT 'user 用户，assistant 助手，system 系统',
  kind VARCHAR(16) NOT NULL COMMENT 'chat、confirm、progress、result、file、delta、done、user',
  body MEDIUMTEXT NOT NULL COMMENT '这一帧的正文。流式增量在读出时再拼成一条',
  project_id VARCHAR(64) NOT NULL DEFAULT '' COMMENT '项目编号',
  problem_id VARCHAR(64) NOT NULL DEFAULT '' COMMENT '问题编号',
  request_id VARCHAR(64) NOT NULL DEFAULT '' COMMENT '确认请求编号',
  stage VARCHAR(40) NOT NULL DEFAULT '' COMMENT '进度阶段名',
  url VARCHAR(512) NOT NULL DEFAULT '' COMMENT '结果链接或文件链接',
  decision VARCHAR(16) NOT NULL DEFAULT '' COMMENT '确认决定：accept、reject，或空',
  file_name VARCHAR(120) NOT NULL DEFAULT '' COMMENT '文件名',
  percent INT NOT NULL DEFAULT -1 COMMENT '进度百分比。-1 表示没有进度',
  created_at DATETIME(3) NOT NULL COMMENT '消息时间，北京时间',
  PRIMARY KEY (id),
  KEY idx_conv (conversation_id, id),
  KEY idx_user (user_id, conversation_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 接口

浏览器只访问客服窗口自己的地址，例如 `http://主机:4100`。客服窗口核对 cookie `xd_customer` 后，用登录时拿到的 frp 令牌转发到 `FRP_HTTP_URL`。页面脚本拿不到这个令牌。

下面每个接口都写两条地址。上面是浏览器调用的地址，下面是 frp 上的同一路径。请求体和响应体相同。

未登录时客服窗口返回 HTTP 401，正文 `{"error":"未登录"}`。令牌失效时 frp 返回 HTTP 401，正文 `unauthorized`。

### 查询会话列表

`GET /api/conversations`

`GET {FRP_HTTP_URL}/api/conversations`

请求参数：无。登录名从令牌里的账号取出，不接受调用方传入 `userId`。

处理时先把该登录名最近 400 条带会话编号的 JSON 消息补进上面两张表（每个进程、每个登录名只补一次），再返回未删除的会话，最多 50 条。置顶在前，置顶之间按 `pinned_at` 倒序，其余按 `updated_at` 倒序。

响应 HTTP 200：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| items | 数组 | 会话列表，不含消息正文 |
| items[].id | 字符串 | 会话编号 |
| items[].title | 字符串 | 标题 |
| items[].renamed | 布尔 | 是否已重命名 |
| items[].pinned | 布尔 | 是否置顶 |
| items[].pinnedAt | 数字 | 置顶时间的毫秒时间戳。未置顶为 0 |
| items[].createdAt | 数字 | 创建时间的毫秒时间戳 |
| items[].updatedAt | 数字 | 最近更新时间的毫秒时间戳 |

```json
{
  "items": [
    {
      "id": "383100000000000001",
      "title": "你会做什么",
      "renamed": false,
      "pinned": true,
      "pinnedAt": 1763876400000,
      "createdAt": 1763870000000,
      "updatedAt": 1763876400000
    }
  ]
}
```

### 查询一个会话和它的消息

`GET /api/conversations/{id}`

`GET {FRP_HTTP_URL}/api/conversations/{id}`

路径参数：

| 参数 | 说明 |
| --- | --- |
| id | 会话编号。4 到 64 位字母、数字、下划线或减号。`inbox` 不接受 |

只返回属于当前登录名、且未删除的会话。消息按编号升序，最多 200 条。`delta` 按 `stream_id` 拼到同一条；`done` 的正文不为空时换成完整正文，并结束流式状态。没有前置 `delta` 的 `done` 不显示。

响应 HTTP 200 的 `item` 字段与列表中的一条相同，并多一个 `messages`。HTTP 404 时正文 `{"error":"会话不存在"}`。编号不合法时 HTTP 400，正文 `{"error":"会话编号不正确"}`。

`messages[]` 的字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | 字符串 | 消息雪花 ID |
| clientMsgId | 字符串 | 浏览器消息编号。没有时与 `id` 相同 |
| conversationId | 字符串 | 会话编号 |
| role | 字符串 | `user`、`assistant`、`system` |
| kind | 字符串 | `chat`、`confirm`、`progress`、`result`、`file` |
| text | 字符串 | 展示正文 |
| time | 字符串 | 北京时间，`yyyy-MM-dd HH:mm:ss` |
| projectId | 字符串 | 项目编号 |
| problemId | 字符串 | 问题编号 |
| requestId | 字符串 | 确认请求编号 |
| stage | 字符串 | 进度阶段 |
| url | 字符串 | 结果或文件链接 |
| streamId | 字符串 | 流式编号。普通消息为空字符串 |
| decision | 字符串 | `accept`、`reject` 或空字符串 |
| fileName | 字符串 | 文件名 |
| percent | 数字 | 进度。没有时为 -1 |
| pending | 布尔 | 固定为 false。只有当前页面刚发出、库还没返回的消息会在页面上暂时为 true |
| streaming | 布尔 | 流式是否还没结束 |

```json
{
  "item": {
    "id": "383100000000000001",
    "title": "你会做什么",
    "renamed": false,
    "pinned": false,
    "pinnedAt": 0,
    "createdAt": 1763870000000,
    "updatedAt": 1763871000000,
    "messages": [
      {
        "id": "383100000000000088",
        "clientMsgId": "383100000000000099",
        "conversationId": "383100000000000001",
        "role": "user",
        "kind": "chat",
        "text": "你会做什么",
        "time": "2026-11-23 13:40:00",
        "projectId": "",
        "problemId": "",
        "requestId": "",
        "stage": "",
        "url": "",
        "streamId": "",
        "decision": "",
        "fileName": "",
        "percent": -1,
        "pending": false,
        "streaming": false
```

### 重命名、置顶

`PATCH /api/conversations/{id}`

`PATCH {FRP_HTTP_URL}/api/conversations/{id}`

路径参数 `id` 与上面相同。请求体是 JSON，两个字段都可以只传一个。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| title | 字符串 | 否 | 新标题。去掉首尾空白，连续空白收成一个空格，最长 40 字。空标题返回 400 `{"error":"标题不能为空"}`。保存后 `renamed` 变为 1 |
| pinned | 布尔 | 否 | true 置顶并写下 `pinned_at`。false 取消置顶并清空 `pinned_at` |

两个字段都没有时，HTTP 400，正文 `{"error":"没有要修改的内容"}`。会话不属于当前登录名，或已经删除时，HTTP 404，正文 `{"error":"会话不存在"}`。

成功时 HTTP 200，正文 `{"item":{...}}`。`item` 的形状与「查询一个会话」相同，包含消息。

```json
{ "title": "改过的名字" }
```

```json
{ "pinned": true }
```

### 删除一条会话

`DELETE /api/conversations/{id}`

`DELETE {FRP_HTTP_URL}/api/conversations/{id}`

路径参数 `id` 与上面相同。这是软删除：写下 `deleted_at`，列表不再返回。`conversation_message` 和 `message` 里的原文不删。

成功时 HTTP 200：

```json
{ "ok": true }
```

编号不合法时 HTTP 400，正文 `{"error":"会话编号不正确"}`。

### 一次删除多条

`POST /api/conversations/delete`

`POST {FRP_HTTP_URL}/api/conversations/delete`

供左侧「多选」使用。请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| ids | 字符串数组 | 是 | 会话编号。去重后最多 50 个。空数组返回 400 `{"error":"请选择要删除的会话"}` |

只删除属于当前登录名、且尚未删除的编号。别人的编号会被忽略。

成功时 HTTP 200：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| ok | 布尔 | 固定 true |
| deleted | 数字 | 这次请求里接受的编号个数，包含已经不存在的编号 |

```json
{ "ids": ["383100000000000001", "383100000000000002"] }
```

```json
{ "ok": true, "deleted": 2 }
```

### 发送消息的原有通道

会话行不是由上面的接口创建的。用户在页面里发送时，仍然走原来的 WebSocket：

`GET /ws`，升级后发送 JSON。客服窗口转发到 frp 的 `/ws?role=external&userId={登录名}`。

发出的 JSON 仍由 `buildFrpPayload` 生成。不能使用字段名 `text`，也不能把正文字符串放进 `content`，否则 frp 只保存那一段，会话编号会丢，这张会话表就收不到。

frp 把 JSON 写入 `message` 之后，立刻按下面的规则写入 `conversation` 和 `conversation_message`。因此换一个浏览器再打开，能看到已经发出和已经收回的那些带会话编号的消息。

## 业务逻辑

页面不再读写 `localStorage` 键 `xd-customer:{登录名}`。会话列表、标题、置顶、删除标记和消息正文都以数据库为准。关联项目的勾选也只留在当前页面内存里，刷新后重新选。

1. 打开页面并确认登录后，立刻 `GET /api/conversations`。失败时提示「会话列表暂时读不出来」，不使用浏览器里的旧列表。
2. 页面处于前台时，每 4 秒再请求一次列表。切回这个标签或窗口获得焦点时也请求一次。另一个浏览器里的重命名、置顶、删除和新会话，会在这一轮出现。
3. 点开一条会话时 `GET /api/conversations/{id}`，之后同一轮轮询也会刷新当前会话的消息。
4. 当前页面通过 WebSocket 刚收到的消息先画出来。下一轮接口结果按消息编号和 `clientMsgId`、`streamId` 对齐，不把还在发送或仍在增长的那条盖掉。
5. 第一条用户消息入库时，如果标题还是「新的对话」，标题取这条正文：折叠空白后最多 18 个字，超出加省略号。`renamed = 1` 之后不再改标题。
6. 重命名调用 `PATCH`，正文 `{"title":"..."}`。置顶和取消置顶调用 `PATCH`，正文 `{"pinned":true}` 或 `{"pinned":false}`。
7. 菜单里的删除和多选后的删除都调用 `POST /api/conversations/delete`。单条删除也可以用 `DELETE /api/conversations/{id}`。删除只是隐藏，不删 `message` 里的传输记录。
8. 分享只把标题和正文复制到剪贴板，不写数据库，也不生成链接。
9. 列表排序：置顶在前，多个置顶按置顶时间倒序，其余按最近更新时间倒序。最多显示 50 条会话，每条会话最多带出 200 条消息。
10. 一条消息归入会话的规则：
    - 外网发进来的消息，所属登录名是 `from_user_id`。
    - 内网发出去的消息，所属登录名是 `to_user_id`。接收人是 `internal` 或空时不归入任何会话。
    - JSON 里要有合法的 `conversationId`，且不能是 `inbox`。
    - 只有 `{ "text": "..." }` 这种正文时，会话编号已经在入库前丢掉，补不进会话表。内网回复要带 `conversationId`，换浏览器才能在对应会话里看到。
    - 会话已经软删除时，后来的消息不再把它重新放回列表。
11. 「开启新对话」只是清空当前选中的会话。第一条消息发出并入库之后，各个浏览器的列表里才会出现它。

上线时先更新并重启 frp，让它建表并提供 `/api/conversations`。然后再更新客服窗口。若只更新客服窗口，旧的 frp 会把这个路径当成一条普通数据请求收进去。
